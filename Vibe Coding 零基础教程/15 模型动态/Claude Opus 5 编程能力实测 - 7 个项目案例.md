# Claude Opus 5 编程能力实测 - 7 个项目案例

> 号称半价追平旗舰，用 7 个真实项目验证一下 Opus 5 到底几斤几两

大家好，我是程序员鱼皮。

前几天 Anthropic 发布了 Claude Opus 5，官方宣称它只用一半的价格，就能把能力追平自家最贵的 Claude Fable 5 旗舰模型。

这个模型的跑分确实很能打。比如 Frontier-Bench 这个测试，专门考察模型能不能在命令行里独立做完一整套编程任务，Opus 5 拿了 43.3%，上一代 Opus 4.8 只有 18.7%，顶配的 Fable 5 是 33.7%，OpenAI 的 GPT-5.6 Sol 是 37.5%。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/hoaffmcwsaa1d-x-20260728104640570-13f9ac34a2)

但是跑分不能完全相信，模型好不好用，还得拿真实项目来检验。

所以这篇文章我会用 **7 个不同类型的项目** 来实测 Opus 5 的编程能力。为了能和其他模型公平对比，我用的提示词跟之前测 Kimi K3 时一模一样（可以阅读本教程模型动态板块中的《Kimi K3 编程能力实测 - 7 个项目案例》了解那次测试）。

测试方法很简单，我在 Cursor 里同时开了多个子 Agent，每个 Agent 分配一个独立的项目目录和独立的端口，全程不需要人工干预，等跑完了我再一个一个验收。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/image-20260728101254851-3c7796013c)

激动的心，颤抖的手，咱们开始~



## 7 个测试项目

这次准备的 7 个项目，从简单的前端动画到复杂的全栈产品，由浅入深：

1. 交互式动画讲解网站
2. 3D 版动画知识讲解
3. 文案拆解为网页 PPT
4. 网页 PPT 生成工具（内置 AI 大模型）
5. 足球对战网页游戏（横评对比）
6. 以撒的结合肉鸽游戏
7. 全栈 AI 编程工具（复刻 Cursor）

大家可以猜猜看，跑完这些任务要花多少钱？答案在结尾揭晓。



### 1、交互式动画讲解网站

第一个项目，让模型做一个用交互式动画讲解知识的网站，讲的知识点是「注意力残差」。

提示词里我要求它先用 Firecrawl 联网搜索技术细节，做完之后自己打开截图验证效果，不满意就自主调整，改到满意再交付。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/image-20260717111349321-20260717144613538-202607-6240ff2b81)

来看成品，界面科技感满满，背景还有漂浮的光点特效。

而且整个网站很清晰、很结构化，读者可以像看教程一样连贯地学会这个知识，也可以通过左侧的章节导航快速跳转、查漏补缺。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785144666553-66077ab6-a75d-4730-84d7-963dc05f8a-73b3ddbb4b)

第一部分它用「一张越写越花的便利贴」来引出问题，这个比喻很生动。你可以拖动滑块来增加堆叠的层数，能亲眼看到第 1 句话在最终画面里的份量越来越少，最后基本读不清了。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785144739223-15eb9fb7-2cd2-440e-824c-3e44e9e10b-c301c2697f)

不过页面上存在一些瑕疵，比如出现了文字被遮挡的情况，这点比 Kimi K3 的前端效果差了一些。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785144789542-88677a5c-d92a-4a8d-8be9-cc13e3bce7-e0b6a2aa89)

但大多数动画效果和元素位置都是准确的，比 Opus 4.8 做动画网站的体验好太多了。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785144946281-9a41c9f8-f0ab-4b60-864e-28c26c6b65-1ab15a7cb2)

它甚至还给出了几道题目来检测学习效果，选错了会告诉你为什么错，细节很到位。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785144892860-fed3bc03-d72a-4b79-aa9d-f904fec855-2b363ae7df)



### 2、3D 版动画知识讲解

还是同一个知识点，这次换成 3D 场景来呈现。

提示词里除了联网搜索，我还要求它用 Context7 查一下所用 3D 库的最新文档，别拿过时的 API 来写。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/image-20260717111408539-20260717144615047-202607-0a7e36c5f4)

来看成品，我刚打开页面就被惊艳到了，科技感爆棚，而且动画非常流畅生动。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145006075-8be31bfa-8f84-466c-ae7d-b58366524c-a370b864fe)

可以自由切换视角、放大缩小，还能并排对比多种不同的残差模式。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145067089-c8c05cfb-e1a3-4f3c-abe8-e3c30aa139-a6039dc1f7)

从事教育行业的朋友有福了，可以让 AI 把枯燥的知识点通过动画栩栩如生地展示清楚，让学生更快理解。

单从前端的角度，我真的挑不出缺点。



### 3、文案拆解为网页 PPT

我做视频教程的时候，偶尔需要把文章内容做成演示画面，但手动做 PPT 太慢了。

这次我干脆把一篇技术文章丢给它，让它按照文章的讲解顺序，拆成一个能全屏演示的网页 PPT，后续可以当做视频录制的画面素材。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/image-20260717111421384-20260717144616722-202607-7a9c3c194e)

先看封面，这个大标题…… 现在怎么 Claude 也一股子 GPT 味儿了。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145163594-b863aa42-a51d-4440-988e-585ce57ef5-0713e286c2)

整个 PPT 的效果跟其他模型差不多，毕竟我没给 AI 提供图片等素材，无非就那么几种布局。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145204715-e3eaf964-6677-426f-976c-7e3fb229e8-4f3b2f9a5a)

不过科技感还是很足的，对于很多场合下的 PPT 讲演都够用了。比如做毕业设计的同学，直接把自己的项目甩给 AI，毕设答辩 PPT 就搞定了。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145242391-0e506acc-4b23-4167-9d5c-e52a400cb7-e7f0f63bb0)



### 4、网页 PPT 生成工具

前面 3 个都是开胃小菜，接下来该测测它的全栈工程能力了。

上一个案例是给定一篇文章生成 PPT，那能不能把这个能力做成一个通用工具呢？

用户粘贴任意文案，后端调用大模型拆解内容，前端渲染成可演示的网页 PPT，还要支持切换配色主题和导出成独立的 HTML 文件。

需求明确之后，提示词就很简单了。由于涉及到 AI 能力，这里我用新出的 Kimi K3 模型作为给后端调用的模型，注意，项目本身的代码还是 Opus 5 生成的。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/image-20260717111459584-20260717144618089-202607-6b8d7a99ce)

之前用 Kimi K3 生成 PPT 工具的时候，成品非常精简，主页基本上就只有文案输入框和按钮。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1784182758933-6b75a1c9-f922-437b-8c85-0115cdea66-e3683bd5a3)

但 Claude Opus 5 做的更像一个成熟的工具产品。你看左下角那一排配色主题就知道了，极光、象牙、暮色、青薄，名字起得还挺文艺，而且每个主题下面还配了一句定位说明。

而且它还支持填写生成 PPT 的额外要求。注意，我并没有在提示词中提到这一点，是 AI 自己锦上添花的。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145527106-4c6d9e30-ba47-47c2-a8a6-d1c9e4cd0d-682a28c39f)

随便拿我之前的一篇文章来制作 PPT，可以实时看到生成进度，质量很高。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785146087244-153c15ee-6ffe-4f7b-8c8d-8224fe2720-7d951edaab)

切换个主题试试，效果不错吧，还能直接全屏演示或者导出为 HTML：

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785146169709-34ce614b-115b-4713-8a42-e165e9c120-4f248772e4)

整体来说，无论是前端细节还是后端生成逻辑都做得很好，一段提示词直接梭出来一个能用的产品。



### 5、足球对战网页游戏

经常看我文章的朋友应该知道，这个项目是老熟人了。

之前 GPT-5.6 发布的时候，我用同一段提示词让 GPT-5.6 Sol、Claude Fable 5、Grok 4.5 三个模型同时开发了一个叫「2066 决战世界杯」的足球游戏（可以阅读本教程模型动态板块中的《GPT-5.6 三模型横评 - 全栈项目实测》）。这次的提示词跟那时候完全一致，正好拿来做个对比。

先看赛前设置界面，浅绿主题色跟足球场很搭。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145627018-69826233-8f03-4610-8ab7-ae4a152bfa-9ff716b94a)

踢球、换人功能都是正常的，非常流畅。而且注意到细节了没？9 号球员下方有个红色的蓄力槽，给了玩家更多的操作空间。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145802068-9d828079-9355-4afd-95d9-65d3d4e38c-8186a3a10e)

游戏的人机也非常智能，不像其他模型开发出来的人机只会防守，这次的人机甚至还能踢出配合。而且作为玩家，也不是完全没有机会赢过人机，游戏体验非常好。

对比一下之前几个模型的表现。GPT-5.6 Sol 开发的那版，人机不会主动进攻，我打满一整场中等难度，只能以 0 比 0 收场。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1783647330206-bb64786d-95d9-41e5-9d53-4fb42ffdd9-a9a1d831b7)

Grok 4.5 开发的那版，球场渲染有硬伤，换人逻辑也很不顺畅，经常切换到离球最远的那个队友身上。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1783648020795-d1809bda-6c3c-4e36-babf-a3f6e9e494-fb9ab3e292)

Claude Fable 5 开发的那版，球的物理引擎翻车了，球经常会瞬移，根本没法正常玩。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1783648857986-4d1edca9-1496-494c-80b1-096690b34b-6493729e05)

而 Opus 5 不仅在人机智能上突破了，左侧还会实时展示赛况，这也是之前的模型都没有做到的。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785145881584-df6c0f0a-5868-4ebd-9d3a-fec99e57ba-cd1968732c)

美中不足的是，足球场的白线有点儿问题，禁区前面那道罚球弧两端拐进了禁区里面。



### 6、以撒的结合肉鸽游戏

接下来是一个更有挑战性的游戏项目。

以撒的结合是我小时候很爱玩的一款肉鸽游戏，包括随机地牢生成、射击战斗、道具系统、多种敌人和 Boss。

之前我让 Kimi K3 开发过这个游戏，提示词中要求先用 Firecrawl 搜索以撒的结合的游戏机制和美术风格资料，用 Context7 查询所用游戏框架的文档：

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1784212259593-16d5f314-9b40-4651-851b-c61dcf8d8c-fe824989d7)

### 7、全栈 AI 编程工具

最后一个项目，直接把难度拉满。

我让 AI 基于 VS Code 的开源代码，开发一个类似 Cursor 的 Web AI 编程工具，要支持 Editor Window 代码编辑器和 Agents Window 对话工作台两种模式，两个窗口之间可以自由切换。

看看成品，几乎完整地保留了 VS Code 的精髓，比如代码高亮、代码小地图、管理面板、代码搜索等等。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785147124049-912c793e-0915-4843-853b-9848a46115-3ec894aa99)

让 AI 执行个任务试试，你能清晰地看到 AI 的思考信息、工具调用等等。

![](https://pub-5477160dc12c41ee929d51a2e2fa91a1.r2.dev/guide/1785147250942-846cdd2b-a6be-4848-b412-dc1d9e31e0-2d1b8df094)

AI 甚至能够调用终端、自主测试开发出的代码，还能清晰地看到本次改动的文件。

## 写在最后

7 个项目全部跑完了，聊聊我的真实感受。

让我印象最深刻的一点是，Claude 没有完全机械地、用最简单直接不绕弯子的方式完成任务，你让它做什么它就只做什么，而是会在你需求的基础上加一点自己的想法，尽量达到理想的效果。

它不仅后端逻辑强、前端视觉效果也强，还非常注重细节，真的是六边形战士了。**至少对我来说，我暂时想不到什么开发任务是 AI 完不成的。** 如果有，那大概是我没有驾驭好 AI，或者 tokens 不够。

另一个让我印象深刻的点是，Opus 5 确实像官方说的那样，特别爱自己检查作业。Anthropic 甚至专门提醒开发者把提示词里那句「最后记得验证一遍」删掉，你越叮嘱它反而越容易检查上瘾。他们后来干脆把 Claude Code 的系统提示词删掉了 80% 以上，编程跑分一点没掉。关于这套提示词减法的具体做法，可以阅读本教程经验技巧板块「大厂 AI 编程经验」目录中的《Anthropic 官方 - 提示词精简方法》。

当然，这个特性是一把双刃剑，Opus 5 很容易把简单的任务搞复杂，这是 Claude 一贯的通病，也就更废 tokens。

所以如果你想更好地利用 Opus 5 这种级别的模型，还是要在提示词上下点功夫，不是说要写得又臭又长，**而是把需求描述清楚、把 AI 的边界限制好**，否则它搞不好就跑偏了。

最后揭晓谜底，这 7 个任务打包加起来，一共花了我 900 多块。

这就是效果好相应的代价。之前我用 Kimi K3 等国产模型做同样的项目，加起来套餐额度才动了百分之几。

所以还是要根据你的实际需求来选择模型：

- 追求 90 分效果的任务，可以交给 Opus 5
- 只需要 80 分的任务，可以交给 GPT 或者 Kimi K3、GLM-5 这类模型，快、稳、便宜
- 只要及格就好的任务，那就用性价比极高的 DeepSeek

模型没有绝对的好坏，只有合适与不合适。多动手试试不同的模型和工具，用实际项目来感受它们的能力差异，你一定能找到最适合自己的编程搭档。
